ITストラテジスト 午後II

設問アとウの型 ― 攻め1と守り1で、③④⑤⑥⑦を同じ型で書く

③④⑤⑥⑦の過去問24問と見本の見出しを並べると、設問アとウは問題が変わってもほとんど同じ組み方です。アとウを型にしておけば、本番で考えるのは設問イだけになります。〔黄色〕の所だけを、問題に合わせて入れ替えます。

まとめアの型アの組み方（型別）ウの3つの型指摘と改善の一覧過去問の当てはめ 骨子の型ツリー事例設定シート

まとめ

設問ア（約600〜800字）1.1「事業概要と事業特性」は毎回同じ文（事業特性は鮮・人）。そのあとは、A「経営課題と目指す変革」、B「対象のシステム」、C「取り組むことになった経緯と私の立場」から、設問の言葉に合う2つを選んで見出しにする。
設問ウ（約600〜1,000字）型1「説明 → 指摘 → 改善」、型2「協議・調整」、型3「結果の評価 → 更に改善する余地」の3つのどれか（2つの組み合わせもある）。リスクや阻害要因を先に問われたら、3.1に置いてから型1に進む。
  • 指摘と改善は、事例設定シートの部品からそのまま選びます（指摘と改善の一覧）。新しい中身を本番で作らないようにします。
  • 経営層「12億円に見合うのか」→「3段階で投資する」は攻め1と守り1の両方で使えます。ただし段階の中身が違います（一覧の注を参照）。

設問アの型

1.1 事業概要と事業特性毎回同じ・約300字

A社は、地方都市圏で食品スーパー40店舗を展開する小売業で、年間売上高は800億円、従業員は約4,000人である。売上の4割を青果・鮮魚・精肉・総菜などの生鮮食品が占める。

A社の事業特性は、次の2点である。第一に、日持ちしない生鮮品の比率が高く、天候や曜日、地域の行事によって需要が大きく変動する点である。このため、発注の精度が欠品と廃棄の量を左右し、利益に直結する。第二に、店舗業務の多くをパート・アルバイトが担っている点である。このため、業務の仕組みは、誰でも短時間で使えるものでなければ現場に定着しない。

  • 第二の特性は、どの型でも「人（パート）」です。DX（③）でも替えません。人の特性は、変革を店舗に根付かせる条件（誰でも使える仕組み）として、設問ウの阻害要因（店長が予測を使わない）や工夫（店長が修正できる形）につながります。
  • ⑥（リスク）は、第一の特性の「このため」を「毎朝の発注が翌日の売場を決める。発注が止まると、翌日の売場から生鮮が消える」にします。事業継続計画（H24問2）は、地域の食品供給の拠点として災害時も営業を続ける協定（社会的責任）を足します。

A 経営課題と目指す変革③⑦、④のH25・H28

解決すべき経営課題は、客数の減少と食品ロスによる利益の圧迫である。客数は5年で1割減少し、生鮮品の廃棄は売上の2%、年16億円に達していた。

これらの課題の根本には、発注を各店舗の店長の勘と経験に頼っていることがあった。経験の浅い店長ほど発注が外れ、欠品と廃棄の両方が起きていた。

このため、勘と経験に頼る店舗運営から、データで地域の需要を読み、廃棄と欠品を同時に減らす店舗運営への変革を目指した。中期経営計画では、廃棄率を2%から1.4%に下げる目標を掲げた。

「経営戦略」「事業戦略」を問われたら、3段落目の前に「価格ではドラッグストアやネット通販に勝てないため、生鮮の鮮度・品ぞろえと地域密着の接客で差別化し、常連の来店頻度を上げる」を入れます。「事業環境の変化」（R4問2・H23問2）は、1段落目の前に競争（ネット通販・ドラッグストアの出店）を書きます。

B 対象のシステム（と課題）⑤⑥④、⑦のH29問2

何のシステムを扱う論文かで、3つから1つ選びます。

守り1 基幹システム（⑤）

A社の基幹システムは、発注・在庫・会計の業務を担っており、20年前に自社で開発したものである。業務の変化に合わせて改修を重ねた結果、一つの改修が思わぬ箇所に影響する構造になっていた。

課題は次の3点である。第一に、仕組みを理解している社員が2名だけで、数年のうちに定年を迎えることである。第二に、店舗からの改修要望が年200件を超え、対応が追いつかないことである。第三に、データが店舗ごと、システムごとに分かれ、POSデータも本部で週に1回しか集計できないことである。この結果、データ基盤や需要予測といった新しい施策を始めようとしても、基幹システムとの連携に時間と費用が掛かり、経営課題への対応が遅れていた。

攻め1 需要予測による発注の仕組み（⑥、⑦のH29問2）

対象は、全40店の生鮮・総菜の発注を支える、需要予測による発注提案の仕組みである。毎晩POSのデータをデータ基盤に集め、毎朝5時に需要を予測して発注画面に提案する。店長が確認・修正して確定すると、仕入れ先へEDIで送る。

仕組みは、データ基盤と需要予測で、クラウド事業者の機械学習サービスを自社のクラウド環境で利用する。利用者は全店の店長と発注を担うパートで、毎朝7時から発注を始め、午前中に確定する。

攻め1の前段 店舗の発注業務と発注システム（④）

対象は、店長が勘と経験で行う店舗の生鮮品の発注業務と、20年前に自社で開発した発注システムである。各店舗の店長は、毎日午後に翌日分の発注数を決め、発注システムの画面に入力する。発注システムは基幹システムの一部で、前日の販売数と在庫数を表示する。改修を重ねて構造が複雑になっており、店舗からの改修要望は年200件を超え、対応が追いついていなかった。

C 取り組むことになった経緯と私の立場ほぼ全問の最後

〔きっかけ（事実と数字）〕。そこで、〔テーマ（設問の言葉）〕を〔策定・立案・企画〕することになった。私は、情報システム部のシステム企画担当課長として、〔テーマ〕を担当した。

型きっかけ（事実と数字）
③ DX・新技術これまでは前年同日の販売実績で発注の目安を出していたが、天候や行事の変動は反映できず、最後は店長の判断に頼っていた → 機械学習による需要予測の採用を検討した（R6問1「新たな情報技術とその必要性」）
④ 分析・真因店舗運営部から、発注画面に前週の同じ曜日の販売数を出すこと、締め時刻を30分遅らせることを求められた（発注関連の要望は年約80件）→ 店舗の視点だけの部分的な要望の可能性があると考え、全社の視点で分析することにした
⑤ 基幹・刷新仕組みを知る2名が数年で定年を迎え、保守できなくなる前に移す必要があった → 経営層の指示で刷新方針を策定することになった
⑥ リスク・BCP需要予測は3店舗の試行で効果が確かめられ、全店へ広げることが決まった。試行の間にも、データ連携の遅れで予測が7時過ぎまで出ない日が1度あった → 全店展開の計画の中でシステムリスク対応方針を立案することになった
⑦ 評価・調整発注は店長の勘と経験に頼り、POSのデータは週1回の集計で発注に使えていなかった → IT導入の目的を、データで需要を読む店舗運営への変革とした（H29問1）。調整（R3問2）は、主なステークホルダ（経営層・店舗運営部・商品部・経営企画部）と、それぞれの立場の違いを書く

設問ウの3つの型

型1 説明 → 指摘 → 改善いちばん多い

〔経営層／事業部門〕には、〔説明した2〜3点〕を説明した。投資は〔12億円〕で、〔年5億円〕の効果が見込め、約3年で回収できる。〔リスク〕には〔対策〕で備えることを示し、〔承認〕を求めた。

〔社長／店舗運営部長〕からは、〔指摘〕という指摘を受けた。〔理由〕という懸念である。

そこで私は、〔元の計画〕を改め、〔新しい計画〕に変更した。あわせて、〔確かめ方・報告の仕組み〕。この改善により〔承認され〕、〔結果〕。

攻め1 で入れると（R6問1）

経営会議では、技術検証の結果と、2つのリスクとその対策を説明した。投資額は基幹の刷新とデータ基盤を含めて12億円で、全店展開で年約5億円の効果が見込め、約3年で回収できる。欠品のリスクには店長の確定と昼の追加提案で備えることを示し、全店展開の承認を求めた。

社長からは、3店舗の結果だけで40店舗すべての効果を見込むのは楽観的ではないか、という指摘を受けた。立地や客層の違う店舗では、同じ効果が出るとは限らないという懸念である。

そこで私は、全店に一度に展開する計画を改め、まず生鮮品の売上が大きい10店舗に展開し、3か月後に廃棄率と欠品率を確認してから残りの店舗に広げる計画に変更した。あわせて、店舗ごとの効果を毎月の経営会議で報告することにした。この改善により全店展開は承認され、最初の10店舗でも廃棄率が平均0.6ポイント下がった。

守り1 で入れると（R7問1）

経営会議では、刷新の必要性、投資と効果、移行のリスクの3点を説明した。刷新と連携基盤への投資は、需要予測を含めて12億円である。保守費の3割削減と、需要予測による食品ロスの削減で年5億円の効果を見込み、約3年で回収できる。移行のリスクについては、段階移行と並行稼働により店舗の発注を止めない計画であることを示し、刷新方針の承認を求めた。

社長からは、刷新の必要性は理解できるが、効果が出る前に12億円を一度に投じるのは負担が大きいという評価を受けた。

そこで私は、一括で投資する計画を改め、3段階で投資する計画に変更した。第1段階は会計の移行と連携基盤の構築、第2段階は発注・在庫の移行、第3段階は店舗業務の移行と需要予測の全店展開とした。各段階の終わりに、保守費と移行の品質を経営会議で確認し、次の段階に進むかを判断する。この改善により刷新方針は承認され、第1段階の会計の移行を予定どおり完了できた。

  • 評価された点も1文書きます（例：「経営層は、立場の異なる2部門の合意を得て構想をまとめた点を評価した」R3問2）。指摘だけで終わらせません。
  • 相手が「事業部門」なら店舗運営部・商品部、「経営層」なら社長・担当役員にします。両方を問われたら、事業部門 → 経営層の順に型1を2回書きます（R5問2・R7問1）。

型2 協議・調整④、R7問1の事業部門、R7問2の協議

私は、〔部門A〕、〔部門B〕、情報システム部で協議の場を設け、まず〔分析の結果・試行の結果〕を共有した。〔部門A〕には、〔データ〕を示して〔説明〕した。〔要望の一部〕は取り入れ、〔見送るもの〕は〔影響〕を示して見送ることで合意した。

〔部門B〕からは、〔意見〕という意見が出た。そこで、〔役割分担・決まり〕とすることで合意した。

攻め1の前段 で入れると（R5問1）

私は、店舗運営部、商品部、情報システム部の3部門で協議の場を設け、まず分析の結果と真因を共有した。店舗運営部には、特売の日の廃棄率のデータを示し、要望どおりに画面を改修するよりも、特売や行事の情報の届け方を変える方が欠品と廃棄を減らせると説明した。前週の同じ曜日の販売数の表示は取り入れ、締め時刻の延長は、加工場の仕込みと仕入れ先の配送への影響を示して見送ることで合意した。

商品部からは、特売の内容は仕入れ先との交渉で前日まで決まらないことがあるという意見が出た。そこで、対象品目と予定価格を2日前に暫定で登録し、特売と行事の情報の登録を商品部の業務とすることで合意した。

攻め1 で入れると（R7問2の協議と取り入れた意思）

店舗運営部長からは、AIに発注を任せると欠品が増え、常連客が離れるという意見が出た。商品部長からは、仕入れの判断は商品部の仕事であり、発注を店舗任せにされると仕入れ計画が立てられないという意見が出た。社長からは、効果を確かめながら段階的に投資したいという意思が示された。

私は、これらの意思を対応策に取り入れた。店舗運営部の意見を受けて、欠品を増やさないことを変革の前提条件とした。商品部の意見を受けて、予測を店舗と商品部の共通の基準とした。社長の意思を受けて、試行の結果を見て次に進むかを判断する段階的な計画とした。

型3 結果の評価 → 更に改善する余地平成の問題に多い

〔施策〕の結果、〔比較の相手〕に対して〔指標〕が〔数字 → 数字〕になった。〔経営者〕からは、〔評価された点〕が評価された。

一方で、〔目標との差・残った課題〕が残った。原因は〔原因〕である。今後は、〔改善策〕で〔目標〕を達成する。
